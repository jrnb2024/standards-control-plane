## Proposal Body
PROPOSED DENY-PLANE RULE (Rego SCP-R-*, required policy-check gate). Protects the oracle/Trusted-Core so the fleet building the pipeline cannot edit the thing that grades it.

Provenance: Phase-0 charter v2 §5 (~/Projects/PHASE-0-CHARTER-conformance-lite-v2-2026-07-12.md), from two adversarial red-team rounds (round-1 hole 2/3/4; round-2 D3↔D9, unanchored baseline, DAG-not-in-manifest). Draft for operator review — do not self-approve.

INTENT: separate the ORACLE (TCB) from the system-under-test (SUT); the fleet may READ the TCB but never WRITE it or self-certify a green.

DENY a diff that:
 (a) modifies any path covered by the signed `trust-root.yaml` (harness code, contracts, board.json registry, banned/sanctioned lists, the DAG, migrations/rule-bundles the harness reads as ground truth, the python lockfile + oracle-container digest, CI gate workflows) WITHOUT a fresh hardware-token OPERATOR counter-signature; OR
 (b) marks a board cell non-RED WITHOUT a matching green in the append-only ledger MINTED INSIDE the pinned oracle container by a non-assumable OIDC subject (no SUT-triggered job can assume it) — closes the D3↔D9 'green-printing-press' where an automated merge-queue signs its own greens; OR
 (c) modifies a CI gate, the scanner allowlist, or branch-protection config without an operator signature; OR
 (d) ships a typed board.json status that disagrees with the computed proof outcome (the L2 computed-board invariant; already enforced in harness.py at genesis commit 63250ca).

KEY PROPERTIES: the tcb-manifest is GENERATED by an open()-trace of a sealed harness run (completeness is mechanical, not clerical) and includes the harness's own dependency closure. The trust root is signed ONCE by a hardware token on slow change — NEVER per-green (per-green human signing reintroduces the rubber-stamp bottleneck). Principal separation is verified by a positive test: a merge/admin API call as the fleet identity must return 403. An org audit-log watcher alerts on out-of-band branch-protection / ruleset / force-push events.

BOOTSTRAP: this rule protects the file that says who owns the TCB; it and CODEOWNERS/the org-ruleset are themselves trust-root-manifest entries.
WAIVER: a waiver may never green a capability cell; TCB-path waivers are operator-signed and expiring.
