## What & why

The `audit-changed` plane (the estate's "before you finish a change → `audit_changed` on the diff" rule) structurally could not audit an **adopter** repo's diff. Two field-verified defects (found shipping mapp-pim WS-4, PR jrnb2024/mapp-pim#615; kg-studio hit the same wall earlier as SCP-MCP-E021):

1. **CLI silently audited the wrong repo (the dangerous one).** `changed_audit._repo_root()` **and** `extractor.extract_scope()` both defaulted to `resources.project_root()` (the SCP checkout). Run from an adopter's cwd, `audit-changed` silently diffed **and extracted** SCP's own tree and returned a **false-clean verdict about the wrong repository** (reproduced from `~/Projects/mapp-pim-ws4c`: score 100, `changed_paths` = SCP's `docs/reviews/WP-SCP-020/branch-protection-log.md`).
2. **MCP route had no way to supply the required area hint.** The `audit_changed` MCP tool exposed only `base_ref`/`head_ref`, so an area-inference miss died with an unrecoverable **SCP-MCP-E021**.

## Fix

- `repo_root` threads `changed_audit → build_audit_result → _normalise_scope → extract_scope` (both the git-diff root **and** the content-extraction root — the original framing undercounted the `extract_scope` layer). Default `None` keeps the plain `audit` command + SCP self-dogfood **byte-for-byte unchanged**.
- New `resolve_audit_repo_root()` defaults to the caller's **cwd, never `project_root()`**, and **fails loudly** (`RepoRootResolutionError`) on a non-git root, a base/head ref absent from the tree, or a cwd belonging to a different repo than `--repo-root`.
- CLI gains `--repo-root` (default cwd). ADOPT-001 §10.1's invocation now audits the adopter repo with no flag change.
- MCP `AuditChangedRequest` gains `repo_root`/`subsystem`/`area_hint` (**SCP-MCP-E021 now recoverable**); `repo_root` defaults to the server cwd; the CLI subprocess runs with `cwd=repo_root`.
- **Hardening (R1 safety):** `git_subprocess_env()` strips `GIT_DIR`/`GIT_WORK_TREE`/`GIT_COMMON_DIR`/`GIT_INDEX_FILE` from every git subprocess so ambient `GIT_*` vars can't poison both sides of the cwd/root guard identically; argv uses `--opt=value` form (leading-dash safety).

## Anti-scope

- The CI `policy-check.yml` OPA/Conftest plane is a **separate plane and untouched** (not broken).
- `--write-output` still targets `output_dir()` under the SCP tree — pre-existing, tracked as `FUP-WP-SCP-038-REPO-LOCAL-OUTPUT-001`.
