## What ships

The Standards Control Plane federation primitive — a deterministic pre-merge policy gate that any downstream repo can adopt by pinning a single reusable GitHub Actions workflow.

- **Reusable workflow** at `.github/workflows/policy-check.yml` (`workflow_call` only). Adopters reference it by 40-char commit SHA.
- **Rego policy bundle** under `policies/`. Exactly **three rules** in v1.0.0:
  - **SCP-R-001** — `services.yml` root-shape conforms to SVC-003 auth modes (`mode.user_oidc`, `mode.service_rs256`, `mode.api_key`, `mode.bearer_legacy` with `deprecation_close_date` ∈ `{"2026-06-30", "2026-09-30"}`).
  - **SCP-R-002** — `waivers.json` entry schema (required keys `approved_by`, `created_at`, `expires_at`, `reason`; root must be a JSON array).
  - **SCP-R-003** — ADOPT-001 §11 vendoring-manifest marker presence on `package.json`, `pyproject.toml`, `go.mod` when those files change.
- **Waiver-aware evaluation** — every rule consumes `data.waivers` via `policies/scp_common.rego` shared helpers. A `deny` only fires when no matching unexpired waiver exists.
- **Caller-side `.scp/rule-config.yaml`** override — adopters can disable a rule with a justification + expiry date. Disabled rules emit observability records into the JSON summary.
- **Conflict-gate** at `tests/conflict_gate/` — every shared fixture is evaluated by both the Rego rule and the Python evaluator; disagreement is merge-blocked with `SCP-E005`.
- **Read-back commit-status** on the sibling context `scp/policy-check-readback` posts human-readable text like "2/3 rules enabled, 0 disabled, 1 not applicable" so reviewers see waiver/disabled-rule posture without reading JSON artefacts.
- **Workflow integration test harness** at `.github/workflows/workflow-selftest.yml` + `tests/workflow/` fixtures — pass + fail fixtures verify the gate's correctness on every PR touching `policies/**`, `.github/workflows/policy-check.yml`, or the summary schema.
- **Local reproduction** via `scripts/scp-policy-check` (Bash) / `python -m standards_control_plane.policy_check` (Python). SHA256-locked OPA + Conftest binaries; offline support; same `lib/policy_check_invocation.sh` invocation as CI.
- **MCP server** (Track 2 — landed at WP-SCP-021) for pre-code agent consult with Ed25519-signed receipts. Distributed via PyPI as `standards-control-plane[mcp]` extra.

## Error codes (SCP-E001–E006)

| Code | Meaning | Failure mode |
|---|---|---|
| **SCP-E001** | Infrastructure fetch fail (OPA/Conftest binary unreachable + SHA256 lockfile mismatch) | Fail-closed |
| **SCP-E002** | Bundle load fail (Rego compilation error) | Fail-closed |
| **SCP-E003** | Policy deny — a rule fired and no matching waiver suppressed it | Merge-blocked |
| **SCP-E004** | Break-glass bypass emitted — `scp_bypass: true` set but the three-gate model rejected the bypass | Merge-blocked |
| **SCP-E005** | Conflict-gate disagreement — Rego and Python verdicts diverge on a shared fixture | Merge-blocked |
| **SCP-E006** | Disabled-rule observability record — emitted (informational) when a rule is suppressed by waiver or `.scp/rule-config.yaml` | Non-blocking |

Fail-closed posture on infrastructure errors. No silent skip.

| **TF-D1-001** | WP-SCP-020 §4 020H part 3 canonical adopter template uses repo name without trailing dash | Fix at 020H part 3 authorship |
| **TF-D1-002** | Document fork-PR refusal as mandatory or optional for adopters | Resolve at 020H part 3 |

```yaml

"on":
  pull_request:
    branches: [main]

  contents: read
  statuses: write

  policy-check:
    if: ${{ github.event.pull_request.head.repo.full_name == github.event.pull_request.base.repo.full_name }}
```
