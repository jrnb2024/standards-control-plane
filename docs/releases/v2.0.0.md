# SCP Federation Primitive — v2.0.0 Release Notes

**Released:** 2026-06-10
**Tag:** `v2.0.0` (cut after the WP-SCP-025 Phase 2 PR merges)
**Bump category:** **MAJOR** per `policies/VERSIONING.md` (new rule born at deny blocks previously-passing PRs)
**Decision:** amended D-053 (`docs/decisions/D-053-wp-scp-025-threshold-deny-promotion-2026-06-08.md`, amendment of 2026-06-10)

## What ships

### 1. NEW rule SCP-R-012 — protected-table-migration-marker (born at DENY)

A schema migration (`*.py` under a `versions/` directory) that performs a
destructive / structural DDL operation — `op.drop_table` / `op.drop_column` /
`op.drop_constraint` / `op.alter_column` / `op.rename_table`, or raw-SQL
`DROP` / `ALTER` / `TRUNCATE` / `RENAME` (including `text()`-wrapped and
multiline forms) — without a standalone attestation comment line:

```python
# scp:protected-table-attested
```

…**blocks merge**. The marker is the author's conformance assertion that the
operation does not destructively alter a protected table (the protected-table
LIST stays in Control Tower per D-058 LINKAGE-not-VALUES — SCP gates the
dangerous operation class, never the values). Design:
`docs/reviews/rule-proposals/RULE-006-protected-table-migration-marker.md`.

**Why deny from birth:** the rule gates an irreversible-data-loss class with a
zero-cost remediation (one comment line after a human look). Reversibility is
preserved per VERSIONING invariant 6 — a mistaken deny is a per-adopter
`disable` / `threshold-override` config flip in the ≤24h Renovate cycle, not a
rollback.

### 2. The rule input contract — `policies/rule-inputs.yaml` (the inert-feed P0 fix)

conftest cannot parse arbitrary file formats, so content rules (the SCP-R-003
envelope: `input.source_file` + `input.content`) only see files the feed step
wraps into YAML surrogates. The feed **hardcoded the three vendoring-manifest
basenames** — meaning SCP-R-008 (secrets in committed `.env`) and SCP-R-012
could never receive content on a real PR. Committed at deny, firing never.

v2.0.0 makes the feed **rule-declared**:

- each content rule declares the files it needs in
  `policies/rule-inputs.yaml` (`basename_regex` or `path_regex`, exactly one);
- `scp_policy_check_prepare_manifest_targets` (lib) surrogates the **union**
  of all declared patterns — adding a content rule without extending the feed
  is now structurally impossible;
- **feed-superset invariant:** every declared pattern must match a superset of
  the rule's own Rego applicability gate (over-delivery is filtered by the
  rule and produces zero findings; under-delivery recreates the silent
  blindness this contract exists to kill);
- a missing or malformed contract **hard-fails SCP-E002 in CI** — the gate
  never silently degrades to a narrower feed. Outside CI a *missing* contract
  falls back to the pre-contract built-in R-003 set (with a stderr warning);
  a *malformed* contract hard-fails everywhere.

The contract is resolved relative to the lib inside `.scp-runtime`, i.e. the
**pinned** contract travels with the pinned workflow — adopters get exactly
the feed their `@<sha>` pin describes.

### 3. SCP-R-008 STAYS warn-baseline (amended from the original D-053 draft)

The original D-053 draft promoted SCP-R-008 warn → deny in this release. The
2026-06-10 operator decision amends that: **v2.0.0 is the release that first
makes SCP-R-008 fire at all** (the feed never delivered `.env` content before
the contract), so the rule has zero real-traffic history. It stays in
`WARN_BASELINE_RULES` and **earns deny on observed evidence** — fires
correctly on live PRs, zero false positives over the PRs it sees — not on the
same release that unblinds it ("it works or it doesn't", applied to the
threshold axis: a threshold flip needs observed WORKS, and a rule that has
never fired has no evidence either way).

## Migration guide (MANDATORY for adopters — MAJOR bump)

Per `policies/VERSIONING.md`, bump the SHA pin only after:

1. **Add an amending decision row** in your repo's `DECISIONS.md` (or
   equivalent) acknowledging the v2.0.0 gate change.
2. **Audit your migrations**: any `versions/*.py` performing destructive DDL
   in open PRs needs the `# scp:protected-table-attested` marker (after a
   human confirms the operation is intentional). Merged history is not
   re-evaluated — the gate sees changed files only.
3. **No action for SCP-R-008** — it now fires (you may see new ::warning::
   annotations on PRs touching `.env` files) but cannot block merge.
4. Bump the `@<sha>` pin + `scp-sha` input together as usual.

Cohort blast-radius at release: mapp-pim, control-tower, mapp-doc-agent — all
three consume via pinned `workflow_call`, so nothing changes until each repo
bumps its pin.
