# SCP Federation Primitive — v1.2.0 Release Notes

**Released:** 2026-05-03
**Tag:** `v1.2.0` (cut after PR for slice 023B merges)
**Bump category:** **MINOR** per `policies/VERSIONING.md` (additive opt-in feature)

## What ships

### Opt-in cross-repo scorecard emit (WP-SCP-023 023B / closes D-041)

The reusable workflow gains a new opt-in input:

```yaml
jobs:
  policy-check:
    uses: jrnb2024/standards-control-plane-/.github/workflows/policy-check.yml@<sha>
    with:
      scorecard-emit: true   # opt-in; default false
```

When enabled, the workflow emits `output/scorecards/scorecard-emit.json` alongside the existing `policy-check-summary.json`, carrying aggregated counts for cross-repo scorecard aggregation per WP-SCP-023 (move #5 of the 5-move MVCP — estate-wide observability).

The emit shape (see `schemas/scorecard-emit.schema.json`) carries:

- Aggregate verdict (`allow` / `deny` / `warn`)
- Per-rule counts (raw_findings, denies, waived, rule_config_disabled) for each `SCP-R-NNN`
- Waivers aggregate (active_count, by_rule_id, expiring_within_30d)
- Rule-config aggregate (disabled_rules list, expiring_within_30d)
- Repo / ref / commit / scp_version pin / RFC3339 emitted_at

**The emit NEVER carries waiver content** — no `reason`, `approved_by`, or `waiver_id` strings cross the boundary (per WP-SCP-023 plan-doc invariant 2). Waiver content stays in the source repo's `output/findings/waivers.json`, CODEOWNERS-protected.

### Verification mechanism (WP-SCP-023 023C-side, in development)

The emit artifact is signed via **GitHub Actions Artifact Attestation** (OIDC-based) using `actions/attest-build-provenance`. The aggregator (slice 023C, in development) verifies via `gh attestation verify --signer-workflow jrnb2024/standards-control-plane-/.github/workflows/policy-check.yml@<sha>` — binding each adopter's emit to the SCP reusable workflow at the expected SHA pin. **No SCP private signing key is ever distributed to adopter runners** (per WP-SCP-023 plan-doc §5 step 3 + reserved D-042).

### Workflow permissions delta

The reusable workflow gains a new **`attest-scorecard` job** that declares `attestations: write` + `id-token: write` at JOB level (NOT workflow default level). This job is gated on `if: inputs.scorecard-emit` AND `needs: policy-check`, so opt-out runs never get the OIDC permissions granted at all. Workflow-level permissions remain `contents: read` + `statuses: write` — unchanged from prior versions. Closes 023B R1 MAJ-SAFE-001 (workflow-level OIDC permissions would have exposed adopter cloud-IAM trust to ALL policy-check runs, not just opt-in).

## What changes for adopters

**No mandatory action.** Default-false on `scorecard-emit` means existing wrappers continue to work unchanged.

**To opt in:**

1. Bump your wrapper's SHA pin past v1.2.0.
2. Add `scorecard-emit: true` to the `with:` block.
3. (Optional, lands at slice 023D) Add your repo to `docs/scorecards/opt-in-registry.yaml` in the SCP repo via PR — the aggregator will start consuming your emit on the next weekly cron run.

## How to verify

```bash
# In a repo that has opted in:
gh workflow run policy-check.yml --ref main
# Wait for the run to complete, then download the emit artifact.
# `gh run download --name scorecard-emit` extracts into a subdirectory
# named after the artifact (`scorecard-emit/scorecard-emit.json`):
gh run download <run-id> --name scorecard-emit
cat scorecard-emit/scorecard-emit.json | jq '.verdict, .rule_counts, .waivers_aggregate'
# Verify the OIDC attestation against the SCP reusable workflow path + SHA:
gh attestation verify scorecard-emit/scorecard-emit.json \
  --signer-workflow jrnb2024/standards-control-plane-/.github/workflows/policy-check.yml@<sha>
```
